# 3X-UI KIT Cascade — экспериментальная надстройка

> **Ветка `cascade-dev` — прототип, не проверенный на боевых VPS.** Не запускайте команды `*-apply --yes` на рабочем сервере без бэкапа и консоли провайдера. Основной `kit` не заменяется.

## Архитектура

Клиенты IPv4/TCP/UDP → сервер A (существующий KIT/3X-UI) → Xray VLESS/REALITY по IPv6/TCP → сервер B (только Xray-core) → интернет.

Сервер A продолжает принимать клиентские подключения по IPv4 и отвечать клиентам по IPv4. Внутренний Xray направляет клиентский трафик через B. Это **не** системный VPN: исходящие процессы Ubuntu автоматически не перехватываются.

## Установка кода из GitHub

На **каждом** сервере можно клонировать ветку непосредственно из GitHub:

```bash
sudo apt-get update
sudo apt-get install -y git python3
git clone --branch cascade-dev https://github.com/MasterriProtos/3X-UI_KIT-Cascade.git
cd 3X-UI_KIT-Cascade
python3 cascade/kit_cascade.py --help
```

Это лишь загрузка кода, **не изменение сетевых настроек**. Исполняйте `python3 cascade/kit_cascade.py` из клонированного каталога; `sudo` требуется для команд записи.

## B: подготовка

Xray-core (официальный бинарник) должен быть установлен заранее и доступен как `/usr/local/bin/xray` или `/usr/bin/xray`. Укажите **реальный глобальный IPv6 B** и пригодный SNI:

```bash
sudo python3 cascade/kit_cascade.py exit-init --ipv6 YOUR_B_IPV6 --sni YOUR_SNI --port 24443
sudo python3 cascade/kit_cascade.py exit-apply
```

Первый вызов создаёт `/etc/kit-cascade/exit/exit-config.json` (приватный ключ B!) и `peer.json` (данные подключения A); второй только валидирует конфигурацию Xray. Команда `exit-apply --yes --restart` заменит текущий `/usr/local/etc/xray/config.json` с резервной копией и перезапустит Xray: пока **не используйте на сервере с существующей конфигурацией**.

В файрволе B вручную разрешите TCP/24443 только с IPv6 A; не открывайте панель или SSH без нужды.

## A: предварительная проверка

Передайте `peer.json` с B на A **защищённым каналом** в `/etc/kit-cascade/peer.json` с правами `600`. Никогда не коммитьте его в публичный репозиторий.

```bash
sudo bash -c 'set -a; source /etc/x-ui/install-result.env; set +a; python3 cascade/kit_cascade.py entry-plan --output /root/cascade-preview.json'
```

`entry-plan` не меняет панель. Проверьте выходной JSON и обязательно убедитесь, что существующие служебные маршруты сохранены. Команда `entry-apply --yes` (пока **не использовать без тестового стенда**) перезаписывает Xray-шаблон панели через локальный API, предварительно сохранив резервную копию. При несовпадении API вашей версии 3X-UI возможны ошибки.

## Изоляция исходящего доступа

`firewall-plan` **только выводит черновик** nftables; не применяет его:

```bash
python3 cascade/kit_cascade.py firewall-plan --peer /etc/kit-cascade/peer.json
```

Файрвол не включается автоматически. До его настройки на A возможны прямые соединения системных процессов. Для безопасной постоянной политики нужны индивидуальные сведения о SSH, IPv4/IPv6, UFW, RA/DHCPv6, сетевых интерфейсах и аварийном доступе.

## Нерешённое в v0.1

- Автоматическое создание отсутствующего MTProto и интеграция nginx/подписки не реализованы.
- AmneziaWG/AmneziaWG 3.1 ещё не прошли проверку UDP и совместимости клиента.
- Не реализован системный прозрачный прокси, автоматическое применение kill switch и безопасный откат firewall.
- Не подтверждена работа локального API панели именно на вашей версии.
- Туннелирование UDP через TCP может увеличить задержку при потерях.
- Оригинальные обновления KIT остаются привязаны к upstream, а не к этому форку.

**Цель этого PR:** добавить основу кода и документацию для безопасного развития, без перехода боевого сервера на непроверенную конфигурацию.
