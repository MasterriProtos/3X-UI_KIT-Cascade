# KIT-Cascade

**Многоузловое подключение на базе 3X-UI KIT и Xray.** Клиент подключается к входной ноде, а исходящее соединение проходит через одну или несколько промежуточных нод до выходной.

```text
                  Клиентские приложения
                           │
                           ▼
                    ┌─────────────┐
                    │    ENTRY    │  Панель 3X-UI KIT,
                    │ Входная нода│  пользователи, подписки
                    └──────┬──────┘
                           │  защищённое соединение
                           ▼
                    ┌─────────────┐
                    │    RELAY    │  Необязательная
                    │ Промежуточная│  нода (может быть несколько)
                    └──────┬──────┘
                           │
                           ▼
                    ┌─────────────┐
                    │    EXIT     │  Выходная нода
                    └──────┬──────┘
                           │
                           ▼
                        Интернет
```

> **Состояние:** версия Cascade v2 в ветке `multi-hop-v2` проходит практическое тестирование. Устанавливайте её на **чистые серверы**, а не поверх работающего KIT.

## Роли и порядок установки

| Роль | Что делает | Когда устанавливать |
|---|---|---|
| **EXIT** | Выпускает трафик в интернет и создаёт защищённый вход для следующей ноды | **1. Первой** |
| **RELAY** *(по желанию)* | Пересылает трафик к следующей ноде без клиентской панели | **2. Между EXIT и ENTRY** |
| **ENTRY** | Принимает подключения пользователей через 3X-UI KIT и направляет клиентский трафик по цепочке | **3. Последней** |

Минимальная схема: **Клиент → ENTRY → EXIT → Интернет**. Если нужны промежуточные ноды, разворачивайте цепочку от EXIT к ENTRY: сначала создайте EXIT, затем ближайший к нему RELAY, потом следующий RELAY, и в конце ENTRY.

## Требования

- **Чистая Ubuntu 24.04** на каждой ноде, доступ `root` через SSH, systemd.
- Доступный **IPv6 между нодами**. EXIT и RELAY публикуют VLESS/REALITY-ссылку для предыдущей ноды; ENTRY должен иметь возможность подключиться к следующей ноде.
- Доступ к настройкам сетевого экрана провайдера, чтобы разрешить нужные входящие порты.
- Свободные требуемые порты; для ENTRY набор портов зависит от выбранных протоколов.

Установщик не перекрывает SSH, не включает системный kill switch и не настраивает автоматически сетевой экран провайдера. Подготовьте резервный доступ к серверу.

## Быстрая установка

Подключитесь к **первой, выходной ноде** по SSH. Команда ниже скачивает небольшой bootstrap-скрипт, который проверяет ОС, устанавливает базовые зависимости (`git`, `python3`, `curl`, `ca-certificates`, `iproute2`), клонирует эту ветку в `/opt/kit-cascade` и запускает интерактивный мастер:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/MasterriProtos/3X-UI_KIT-Cascade/multi-hop-v2/bootstrap.sh)
```

Запускайте от `root`. Для установки через `sudo` сначала скачайте файл и изучите его:

```bash
curl -fsSLo bootstrap.sh https://raw.githubusercontent.com/MasterriProtos/3X-UI_KIT-Cascade/multi-hop-v2/bootstrap.sh
less bootstrap.sh
sudo bash bootstrap.sh
```

> Команда с `<(curl ...)` сохраняет интерактивный ввод мастера. **Не** используйте `curl | bash`: установка требует терминал и ввод секретной ссылки.

Мастер предложит роль. Можно передать её явно: `bash bootstrap.sh --role exit`, `--role relay` или `--role entry`.

### Шаг 1 — EXIT

Выберите **EXIT**. Мастер попросит IPv6, TCP-порт и домен маскировки REALITY. После проверки соединения будет создана **VLESS-ссылка для следующей ноды**. Храните её как пароль, не публикуйте и не присылайте в общие чаты.

### Шаг 2 — RELAY (если нужен)

На следующем чистом сервере запустите тот же bootstrap и выберите **RELAY**. Вставьте защищённую ссылку от EXIT. RELAY проверит маршрут и выдаст **свою** ссылку для предыдущей ноды.

Для нескольких RELAY повторяйте этот шаг, двигаясь к ENTRY.

### Шаг 3 — ENTRY

На последнем чистом сервере запустите тот же bootstrap и выберите **ENTRY**. Вставьте ссылку от EXIT или ближайшего RELAY. Затем мастер 3X-UI KIT предложит выбрать пользовательские протоколы и настройки панели. После установки добавляйте пользователей и получайте подключения через меню `kit`.

## Управление и проверка

После установки репозиторий находится в `/opt/kit-cascade`.

| Задача | Команда на нужной ноде |
|---|---|
| Статус EXIT/RELAY | `sudo python3 /opt/kit-cascade/cascade_v2/install.py status` |
| Показать ссылку EXIT/RELAY | `sudo python3 /opt/kit-cascade/cascade_v2/install.py show-link` |
| Статус ENTRY | `sudo python3 /opt/kit-cascade/cascade_v2/install.py entry-status` |
| Проверка маршрута ENTRY | `sudo python3 /opt/kit-cascade/cascade_v2/install.py entry-probe` |
| Проверка MTProto-моста | `sudo python3 /opt/kit-cascade/cascade_v2/install.py entry-mtproto-probe` |
| Пользователи и протоколы ENTRY | `sudo kit` |

В случае неудачной установки **не запускайте bootstrap повторно поверх существующей ноды**. Посмотрите диагностику и процедуры восстановления в [расширенной инструкции](cascade_v2/README.md) и [руководстве ENTRY](cascade_v2/ENTRY.md).

### Особенности MTProto

Если при установке ENTRY выбран MTProto, для него может использоваться отдельный TCP-порт **8445** — без маршрутизации по SNI. Доступность сервиса зависит не только от сервера, но и от сети клиентского оператора. Настройка MSS, помогшая одному клиенту, **не считается универсальным решением** и намеренно не применяется bootstrap-скриптом автоматически.

## Безопасность и ограничения

- Секреты, VLESS-ссылки, конфигурационные файлы и резервные копии должны оставаться **только на серверах**, а не в Git-репозитории.
- Не публикуйте полные отладочные журналы MTProto: они могут содержать действующие секреты и токены.
- Bootstrap предназначен **для первичной установки**, а не для обновления существующего KIT. Входная нода использует штатное управление `kit`.
- Клиентский трафик маршрутизируется цепочкой; исходящие соединения **самой ОС** (например, `apt`) автоматически не туннелируются.
- Использование и настройка проекта — ответственность владельца нод.
