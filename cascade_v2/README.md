# KIT-Cascade v2 — EXIT / RELAY (экспериментальная alpha)

> **Не объединять с main до тестов.** Этот каталог содержит самостоятельный установщик чистой Ubuntu 24.04 только для EXIT и RELAY. Функция ENTRY с оригинальной панелью 3X-UI KIT будет разрабатываться отдельно.

Схема развёртывания **справа налево**:

```text
Client IPv4 → ENTRY (KIT, пока не готов) → RELAY 2 → RELAY 1 → EXIT → Интернет
                  устанавливается последним    необязательные    первым
```

Каждый EXIT/RELAY выдаёт ссылку вида `vless://UUID@[IPv6]:24443?...#...`. Для установки следующего узла используется ссылка *уже подготовленного downstream-узла*.

## Что сейчас работает в коде

- Интерактивный выбор EXIT или RELAY на чистой Ubuntu 24.04.
- Выбор глобального IPv6 **из реально назначенных интерфейсам** (без обращения к стороннему IP API).
- Выбор порта TCP, TLS 1.3 / SNI-проверка REALITY target.
- Установка официального Xray-core через XTLS/Xray-install с фиксированной ревизией установщика.
- Генерация независимого UUID, X25519-ключей REALITY и shortId для каждого узла.
- Строгий импорт VLESS-ссылки (IPv6 + REALITY + TCP + Vision), без записи её в консоль.
- Генерация и валидация Xray JSON с помощью **самого Xray-core**.
- Запуск Xray через systemd и реальная проба VLESS → HTTPS через временный локальный SOCKS5-клиент. Проверяемый выходной IP сообщается в терминале.
- Сохранение ссылки в `/etc/kit-cascade/link.txt` только для root (0600).
- Резервная копия первоначального Xray-конфига и автоматический rollback конфигурации и Xray-сервиса, если проверка неудачна.
- Ручная команда `restore`, которая останавливает Xray, возвращает первоначальный конфиг и оставляет бинарник для повторной попытки.
- Офлайн тесты и GitHub Actions с проверкой JSON настоящим Xray.

## Ограничения безопасности — прочитайте до установки

1. **НЕТ изменений SSH/портов SSH, UFW, nftables, iptables, сетевых маршрутов, DNS.** Это намеренно: пока не подтверждён доступ через аварийную консоль провайдера.
2. `RELАY` не имеет Xray-`freedom` или резервного direct-outbound, но **самостоятельные системные процессы Ubuntu по-прежнему могут выходить напрямую**. Полный Linux kill switch пока не реализован.
3. Установщик не открывает порт в облачном файрволе или UFW. Разрешите выбранный TCP-порт для соединений **от предыдущего узла** после установки. SSH не закрывайте.
4. Он **отказывается работать поверх уже существующей чужой установки Xray**. Только чистый VPS или Xray, который остался после нашей команды `restore`.
5. При падении downstream-узла Xray-клиентский трафик на RELAY прерывается, без fallback на `freedom`.
6. Все ссылки и файл JSON содержат чувствительные секреты. **Никогда не загружайте `/etc/kit-cascade` на GitHub и не публикуйте ссылки.**
7. Проверка HTTPS требует доступности `api.ipify.org` с EXIT. Если этот внешний адрес недоступен, установка отменяется и возвращается прежняя конфигурация; это не означает, что сама VLESS-связь обязательно неисправна.
8. Установщик использует актуальный Xray-core. Версии и синтаксис фиксируются на этапе CI; при будущих изменениях Xray требуется проверка совместимости.
9. Без аварийной консоли провайдера избегайте изменений сетевого стека; в текущей alpha они вообще отсутствуют.

## Подготовка немецкого EXIT (не затрагивает российский VPS)

Проверьте, что на VPS действительно чистая Ubuntu 24.04 и есть SSH с sudo, а IPv6 назначен интерфейсу. Проверка из терминала (без установки):

```bash
ip -6 addr show scope global
curl -6 -fsS --max-time 10 https://api64.ipify.org
```

Затем **на тестовом EXIT**:

```bash
sudo apt-get update
sudo apt-get install -y git python3 ca-certificates
git clone --branch multi-hop-v2 https://github.com/MasterriProtos/3X-UI_KIT-Cascade.git
cd 3X-UI_KIT-Cascade
sudo python3 cascade_v2/install.py install --role exit
```

Мастер попросит:
- выбрать IPv6;
- выбрать TCP-порт (по умолчанию 24443);
- указать корректный SNI TLS 1.3 (по умолчанию `www.microsoft.com`);
- подтвердить установку словом **УСТАНОВИТЬ**.

После успеха сохраните VLESS-ссылку безопасно. Используйте `status` для диагностики, `show-link` чтобы снова вывести ссылку. Не публикуйте её в issue.

## RELAY (другой чистый VPS, только если понадобится)

```bash
git clone --branch multi-hop-v2 https://github.com/MasterriProtos/3X-UI_KIT-Cascade.git
cd 3X-UI_KIT-Cascade
sudo python3 cascade_v2/install.py install --role relay
```

При вставке ссылка от EXIT принимается **без отображения символов**; RELAY выдаёт новую ссылку со своим IPv6. Для следующего RELAY повторите процедуру.

## Управление

```bash
cd 3X-UI_KIT-Cascade
sudo python3 cascade_v2/install.py status
sudo python3 cascade_v2/install.py show-link
sudo python3 cascade_v2/install.py restore
```

`restore` требует ручного подтверждения **ВОССТАНОВИТЬ**. Он возвращает Xray-конфигурацию и останавливает `xray.service`, но не удаляет установленный официальный Xray binary. При повторной установке после отката используйте ту же команду `install`.

## Автоматические тесты, без root и без сети

```bash
python3 -m compileall -q cascade_v2
python3 -m unittest discover -s cascade_v2/tests -v
```

CI дополнительно запускает `xray run -test` на сгенерированных конфигурациях EXIT и RELAY.

## Что остаётся до beta

- Полноценный ENTRY: установка панели 3X-UI, сохранение функционала KIT, выбор протоколов, SNI/маскировки, настройка маршрутов Xray.
- Отдельное развёртывание/диагностика MTProto и AmneziaWG.
- Сквозные IPv4/IPv6/UDP пробы в 2–4-хоповых тестовых стендах.
- Безопасная политика системных исходящих соединений с автоматическим откатом после подтверждения аварийной консоли.
- Обновления, ротация credentials, мониторинг каждого перехода, release signing.
